# Proxmox VE NFS + PBS Appliance

Portable Debian 13 Proxmox VE LXC providing **NFS, SMB, SSH/SFTP and Proxmox Backup Server 4**.

## Services (one root password)

- **NFS**: `CT-IP:/srv/nfs` — permissive NFS export for trusted networks.
- **Windows SMB**: `\\\\CT-IP\\nfs` — username `root`.
- **SSH**: `ssh root@CT-IP` — username `root`.
- **SFTP**: `sftp root@CT-IP` — username `root`; files live under `/srv/nfs`.
- **PBS Web UI**: `https://CT-IP:8007` — username `root@pam` (PAM root account).
- **PBS datastore**: `backup` at `/srv/pbs/backup`; **not** exposed via NFS or SMB.

All four authenticated services use the **same Linux root password** stored in the local `ROOT_PASSWORD` variable. The original `nfs-upload` SMB account is disabled on upgrade.

## Requirements

- Debian **13 (trixie)** CT on Proxmox VE; privileged LXC with the NFS server features already enabled.
- Network access for Debian and Proxmox package repositories during first installation.
- **Evaluation**: minimum 2 GiB RAM and more than 8 GiB disk; 4 GiB RAM and a suitably sized CT root volume recommended.
- PBS inside LXC is **not the recommended production deployment**. A dedicated PBS machine or VM on separate failure-domain storage is preferable for recoverable backups.
- The datastore lives within the CT root filesystem so it is included when backing up the CT root volume. Ensure sufficient actual physical ZFS capacity; PBS retention/GC need operational headroom.

## Install in the CT

```bash
apt-get update && apt-get install -y git
git clone https://github.com/pulipulichen/proxmox-ve-nfs-appliance.git /opt/proxmox-ve-nfs-appliance
cd /opt/proxmox-ve-nfs-appliance
./start.sh
```

The installer installs official `pbs-no-subscription` packages (no paid subscription), initializes datastore `backup` once, and checks the services. It does not delete data in `/srv/nfs` or `/srv/pbs/backup`.

**One password**: `/root/.config/proxmox-ve-nfs-appliance/credentials` (root-only mode 0600) contains **only** `ROOT_PASSWORD`. It preserves the existing `ROOT_PASSWORD` generated by earlier versions, removes the obsolete `NFS_UPLOAD_PASSWORD` entry, and synchronizes Linux root and Samba root credentials each run. If no credential exists, it creates a random password.

If upgrading an existing CT, this **sets the Linux root password to the saved ROOT_PASSWORD**. To intentionally rotate the single password on a trusted CT console, use an environment variable for one run (avoid shell history or shared shells):

```bash
read -r -s -p 'New root password: ' ROOT_PASSWORD; echo
export ROOT_PASSWORD
./start.sh
unset ROOT_PASSWORD
```

## Update from GitHub

```bash
cd /opt/proxmox-ve-nfs-appliance
./update.sh
```

`update.sh` performs `git pull --ff-only origin main`, then `./start.sh`. Data and PBS datastore configuration are retained.

## Connect Proxmox VE to PBS

In **PVE > Datacenter > Storage > Add > Proxmox Backup Server**, enter:

- **ID**: e.g. `appliance-pbs`
- **Server**: CT IP
- **Username**: `root@pam`
- **Password**: the saved `ROOT_PASSWORD`
- **Datastore**: `backup`
- **Fingerprint**: fingerprint shown by `proxmox-backup-manager cert info` in the CT, if prompted

After adding storage, select `appliance-pbs` as the destination for a backup job under Datacenter > Backup. PBS server and datastore alone do **not** create a scheduled PVE backup job.

### Windows drive mapping

```cmd
net use Z: \\CT-IP\nfs /user:root *
```

### Read the saved credential locally (change CTID)

```bash
pct exec 104 -- cat /root/.config/proxmox-ve-nfs-appliance/credentials
```

**Do not paste passwords into GitHub, logs or tickets.**

## Security and durability warnings

- **Trusted networks only.** Original NFS export is wildcard + `no_root_squash`, and `/srv/nfs` is world-writable.
- SMB, SSH and SFTP accept direct root credentials. These settings provide complete administrator control and should never be exposed to the internet. Restrict ports **22**, **445**, **2049**, **8007**, and NFS RPC-related ports to trusted networks.
- PBS `pbs-no-subscription` is a free, less-tested repository intended for testing rather than critical production backups.
- **NFS/PBS on the same CT/host is not a separate failure domain.** Do not treat backups stored on the same host and ZFS pool as disaster-recovery copies.
- PBS `backup` datastore is intentionally private; it is *not* part of the SMB/NFS share.
- No automatic backup retention/prune policy is installed, to avoid deleting user backups. Daily garbage collection may run; the user should configure retention intentionally.
